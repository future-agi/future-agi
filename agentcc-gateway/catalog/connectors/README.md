# Connector catalog

One catalog of connectors for the FutureAGI gateway and Omega's managed agents (EE) and framework (OSS). Each app is described once; the gateway, EE and OSS each receive what they can use.

The data is open source (Apache-2.0, like the rest of this directory). It never holds a client id, a secret, a price or a community package.

## Layout

```
catalog/connectors/
  schema/                      published JSON Schemas (draft 2020-12)
    connector-manifest.v1.json       app, provider, platform, tool, tools-generated
    connector-catalog-bundle.v1.json dist/catalog.json
    connector-price-overlay.v1.json  gateway-only pricing (data never lives here)
  apps/<app-id>/
    app.yaml                         the app
    providers/<provider-id>.yaml     one way to reach it
    providers/<provider-id>/
      tools.generated.json           a rest provider's generated tools
      tools.yaml                     the REST generator's curated overlay (its input)
      fixtures/**, evals/**          scrubbed cassettes and eval suites
  platforms/<platform-id>.yaml       a partner platform (Arcade, Composio, ...)
  dist/**                            generated by agentcc-catalog build
```

Any other file under `apps/` or `platforms/` is refused. Ids equal their directory or file names. Apps and platforms share one id space, and `platform` is reserved.

## Records

Every record starts with `schema:` and its kind: `connector-manifest/v1#app`, `#provider`, `#platform` or `#tools-generated`. Each record carries a semver `version`.

- **App**: identity (name, description, vendor domains), EE's category and group, the open categories and tags, `docsUrl`, `defaultProvider`, `lifecycle` and `sources`.
- **Provider**: one of four kinds.
  - `vendor_mcp`: the vendor's remote MCP server.
  - `rest`: our MCP server over the vendor's REST API, served at `https://{connectorsHost}/<app-id>/mcp`.
  - `partner`: a partner platform's server.
  - `vendor_local`: the vendor's local stdio package.
    It carries `transport`, `auth`, `accountModes`, `tools`, `pricing` (the model only, never a number), `quality` and `sources`.
- **Platform**: how the gateway connects to a partner platform, with discovery meta-tools off (`toolMode: fixed`).
- **Tools generated**: `tools.generated.json` holds `{schema, spec: {url, sha256}, tools: [...]}`. `spec` must equal the provider's `upstream.spec`, and its tools use the same shape as `tools.items`.

An earlier sketch of this format wrote `null` for keys it left empty. In real records, **omit the key**: null is refused everywhere except inside a tool's `inputSchema` and `outputSchema`.

### Credentials and OAuth

- `auth.kind`: `oauth2`, `mcp_oauth`, `api_key`, `basic`, `service_account`, `partner`, `none` or `local_setup`.
- `auth.oauth2` is EE's `IntegrationOAuthSpec` field for field, with scopes as a list, plus these extras:
  - `urlVariables`, such as Entra's `{tenant}`;
  - `revocation`, `refresh`, `registration` and `clientGroup`;
  - `review`, the vendor's app review and its lead time;
  - `tokenResponse.accessTokenPath`, for a vendor that returns the token away from the top level (`authed_user.access_token`).
- `auth.credentialParts` lists the parts of an `api_key` credential and where each goes: `in: header | query | url_variable`.
  - A secret part never has a `value`.
  - A non-secret part is either a constant (`value`) or a customer setting.
  - Datadog's two keys and Close's `Close-API-Key` plus `Close-Scope` are two parts each.
- `auth.clientApproval` records a vendor that admits only clients it has approved, such as Figma, Vercel, MongoDB, or Slack's Marketplace.
  - Until `approvedAt` is set, the provider stays at tier `listed`.
- `tools.items[].generic: true` marks a tool whose real operation is one of its arguments, such as Stripe's `stripe_api_write`.
  - `genericArguments` names the arguments that carry the operation.

### URL templates

A URL may hold `{name}` variables anywhere, the host included. Snowflake's `https://{accountUrl}/api/v2/databases/{database}/schemas/{schema}/mcp-servers/{serverName}` is an example.

Each variable is declared exactly once:

- in `transport.urlVariables`, as `{description, pattern, default?, scope: org | user}`;
- or as a `url_variable` credential part.

The `pattern` is anchored (`^...$`), and a `default` must match it. OAuth URLs declare theirs in `auth.oauth2.urlVariables`:

- A variable declared there and in `transport.urlVariables`, such as Snowflake's `{accountUrl}`, is one value, so both declarations have the same `pattern`, `scope` and `default`.
- A variable in the host of `tokenUrl` or `revocation.url` has `scope: org`, never `user`: that host receives the OAuth client's secret.

## Rules

`go test` runs these on every commit. L0 is enforced by the loader, `manifest.LoadDir`; L1 is `manifest.CheckL1`.

**L0**

- The JSON Schema: no unknown key and no null at any level, every value of its type and within its bounds.
- No secret-shaped value in any file, comments and cassettes included:
  - `scripts/release/secrets-lint.sh`'s eight provider-key shapes;
  - Google OAuth client ids and secrets.
  - Each line is scanned, then each decoded string of a JSON, JSON Lines or YAML file, so an escaped key is found too.
  - A record that holds one is not decoded further, and no message quotes a secret.
- Every URL is HTTPS with a lowercase public host, no userinfo and no fragment (EE's `safeEndpoint` and `contactableMcpEndpoint`).
  - A host that ends in a number is an IPv4 address to a URL parser (`127.1`, `0x7f.0.0.1` and `0177.0.0.1` are all `127.0.0.1`), so it is refused unless written in dotted-decimal form.
- Each fact cites a source, as `{fact: <dotted path>, url, fetchedAt}`:
  - which facts: each URL, scope list, rate limit and review lead time, plus `vendor.domains` and `vendor.githubOrgs`;
  - inline: rate limits, review lead times, vendor status labels and client approvals carry their `source` in place;
  - a source must name a field its record has;
  - links that are themselves sources need none (`docsUrl`, `helpUrl`, `termsUrl`, `upstream.spec`), and neither does a rest provider's own URL.
- Kinds agree with their transport, publisher, auth and tool source.
  - An http provider is `hosted`; a stdio provider is not.
  - `trusted: true` only after a maintainer review, at tier `verified` or `optimized`.
- Tools:
  - at most 128 per provider;
  - unique names;
  - `len(app.id) + 2 + len(tool.name) <= 64`, so `<server>__<tool>` fits;
  - `auth.verify.tool` names one of them.
- **OAuth clients.** An `oauth2` provider's client group is its `clientGroup`, else its app id, as the backend resolves OAuth clients (`resolve` in `futureagi/agentcc/services/connector_oauth_clients.py`). A group is one OAuth client, so its providers name:
  - one `tokenUrl`;
  - one `revocation` endpoint (`url` and `clientAuth`), or all name none.
- A provider never forwards a credential header or a header the gateway never forwards (`x-agentcc-*`, `x-omega-*`; `config.ForwardHeaderRefused`), and `pricing.notes` never holds a price.
- **EE**: every app EE receives passes EE's boot rules (below), and at most 64 apps qualify for EE's settings file.
- **OSS**: OSS ids are unique and at most 40 characters, an OSS http server has a fixed URL, and existing OSS ids are never renamed.
- **Public clients**: an `x-omega.publicClient` that says `supported: true` is an `oauth2` sign-in with PKCE and a pre-registered client, proven by the vendor's own pages (see "Public clients" below).

**L1**

- Annotations agree: a read-only tool is not destructive.
- Postures:
  - a write tool is never `auto`;
  - a destructive tool defaults to `deny`.
- Tool schemas are JSON Schema 2020-12: no other `$schema`, no draft-07 keywords, only local `$ref`, and an `inputSchema` root of type object.
- An `operations` source names each REST call and describes each tool.
- The scope union: an `oauth2` provider's tools each list the scopes they need, and together equal the scopes it requests. OpenID scopes need no tool.
- The tools/list estimate (characters / 4) stays within `ToolListTokenBudget` (20,000):
  - checked for the tools we author and at tier `optimized`;
  - a vendor's own server is measured, not refused.
- `SemverDiff(old, new)` gives the required bump, and `CheckVersionBump` refuses a version that does not move by it.
  - **Major**: a tool removed; a required input added without a default; an input or output key removed or renamed; `auth.kind` changed; a scope added; an account mode removed; a credential part or URL variable the customer must now supply; EE's id or env prefix changed; EE or OSS losing what it receives, as when EE takes another provider or an OSS server id, which names its tools, changes.

`CheckPublic` applies the open-data rule to what will be published: no `community` publisher.

## What EE and OSS receive

**EE** takes, per app, the first provider in emission order that:

- uses `oauth2`;
- uses `http`;
- is `vendor_mcp` or `rest`;
- is not excluded.

Emission order is `defaultProvider` first, then the rest by id (`manifest.EligibleForEE`, `manifest.EEAppFor`).

- The id is `x-omega.eeId`, else the app id. The env prefix is `x-omega.envPrefix`, else `OMEGA_INTEGRATION_<ID>`.
- EE's eight built-in apps keep their ids and env prefixes: `gmail`, `google-calendar`, `google-drive`, `slack`, `github`, `linear`, `notion` and `atlassian`.
- EE reads an app's OAuth client from variables under its env prefix, so:
  - no two apps share a prefix, and no other app takes a built-in app's;
  - no app takes `OMEGA_INTEGRATION_GOOGLE`, EE's shared Google client.
- An app in group `google` uses Google's token endpoint, `https://oauth2.googleapis.com/token`, since EE may give it the shared Google client.
- What EE cannot use is refused for an EE-eligible provider:
  - `tokenResponse`;
  - `resourceIndicator`;
  - an OAuth URL variable without a default;
  - a name or description that JavaScript's `trim` would change (a space or an invisible character at either end);
  - an MCP URL longer than 200 characters.
    Set `x-omega.ee: exclude` on the provider or the app until Omega's side widens EE.

**OSS** receives one server per `vendor_mcp` (http) or `vendor_local` (stdio) provider that is not excluded (`manifest.EligibleForOSS`).

- The id is `x-omega.ossId`, else the app id for the first and `<app>-<provider>` for the rest.
- OSS's 15 existing ids keep their app, transport and, for the hosted five, their URL. For example, `github` is the stdio server and `github-remote` the server at `https://api.githubcopilot.com/mcp/`.
- `oss-registry.json` lists only the servers OSS can sign in to (`manifest.OSSListed`). `omega mcp login` is given an authorize URL, a token URL and a client id by hand, sends a PKCE verifier, redirects to loopback, and sends no client secret. So it leaves out:
  - an `oauth2` provider whose `registration` lists `dcr` or `cimd` but not `preregistered` (rule `oauth_client_self_registration_only`): OSS cannot register a client itself;
  - any other `oauth2` or `mcp_oauth` provider whose `x-omega.publicClient` does not say `supported: true` (rule `oauth_public_client_not_proven`): not stated means not proven.
- Such a server keeps its OSS id, and `agentcc-catalog build` names each one, with its rule and what its record says of a public client (yes, no or not stated), in its output and in `dist/README.md`. A change that removes a listed server (its `registration`, or its public client no longer proven) is a major version bump; one that brings it back is minor.

### Public clients (`x-omega.publicClient`)

A provider record states whether a person can sign in the way `omega mcp login` does: with a client id they register with the vendor beforehand (or the vendor publishes), PKCE, a loopback redirect and no client secret.

```yaml
x-omega:
  publicClient:
    supported: true # or false
    evidence: # 1 to 4 saved pages
      - url: https://airtable.com/developers/web/api/oauth-reference
        fetchedAt: 2026-10-22
        sha256: <sha256 of the page as saved that day>
        quote: "Authorization (optional) Required if your integration has a client_secret. forbidden if it does not."
    notes: "optional, at most 500 characters"
```

- Only an `oauth2` or `mcp_oauth` provider has one.
- `supported: true` needs `auth.kind: oauth2` (an `mcp_oauth` record declares no authorize or token URL to type in), `pkce: true` and a `registration` that names `preregistered`.
- Every evidence page for `supported: true` is the vendor's: a host in or under the app's `vendor.domains`, or `github.com/<org>` for one of its `vendor.githubOrgs`.
- Each evidence item names the page, the date it was saved, the sha256 of the saved bytes and the sentence that bears the fact out. A page can change after it was saved, so the quote is what a reviewer looks for.
- `supported: false` cites the page that asks for a client secret. Leave the fact out when no page decides it: the server is then left out as not proven.

## The price overlay

`connector-price-overlay/v1` is the schema for gateway-only prices, keyed `<app-id>/<provider-id>` or `platform/<platform-id>`.

Overlay files are never committed to this repository and never placed under `ee/`, which is public. They live in an operator directory, filled from private sources. The loader refuses an overlay document anywhere in the catalog.

## Validate

```
cd agentcc-gateway
go test ./internal/connectorcatalog/manifest/ -run TestRepoCatalogValid -count=1   # the catalog in this repo
go test ./internal/connectorcatalog/manifest/... -count=1                          # the validator itself
```

`TestSchemaParity` keeps the loader's keys, required keys, patterns, enums and bounds equal to `schema/connector-manifest.v1.json`.

To check the published schema with another JSON Schema 2020-12 validator, export the test corpus:

1. Run `MANIFEST_CORPUS_DIR=<dir> go test ./internal/connectorcatalog/manifest/ -run TestSchemaCorpus`.
2. Validate `<dir>/manifest/valid/*.json` (all must pass) and `<dir>/manifest/invalid/*.json` (all must fail) against `schema/connector-manifest.v1.json`.
