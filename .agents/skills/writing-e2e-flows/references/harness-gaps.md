# Harness gaps

Read **before** writing a flow plan, every time. These are the things the harness cannot do yet. A
flow that needs one of them is blocked, not merely awkward.

## The standing rule

**A `lib/` extension is its own piece of work, planned with the user.** Not a helper defined at the
top of a spec, not a second fixture file added "while I'm here", not a hand-rolled `ApiClient` or
`StateProbe` constructed inline because the fixture did not fit.

When a plan hits a gap, say so in the plan, and offer the user three options:

1. **Narrow the flow** to the part the harness can prove today, and say in the `userGoal` what it no
   longer claims.
2. **Split it**: a `lib/` extension as its own piece of work first, this flow after it.
3. **Drop it** for now and record it as a coverage gap.

Choosing for the user is the failure mode. Silently narrowing the goal — driving an API call because
the product's own path does not reach the state — changes what the flow proves without anyone
agreeing to it.

`e2e/flows/auth/login.spec.ts` bypassing `lib/fixtures` is not a precedent for building your own
actors: it is a documented single-actor exception because it drives the login UI itself.

## The gaps

| Gap                                                                                                                                                                            | What to do instead                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Multiple actors require the separate scope fixture.** `lib/scope-actors.ts` provides two organizations, an extra workspace, public member/viewer invitations and explicit scoped clients. | Use its fixture and `harness/scope-actors.spec.ts` evidence. Do not assemble identities inside a flow. Existing-token default-workspace fallback has a separately recorded cache bug; explicit scope passing does not qualify that path, invite-email delivery, or workspace-specific ingestion keys. |
| **The ordinary actor is worker-scoped.** A shared actor cannot guarantee an empty org or workspace. | Mint names for ordinary flows. Use the test-scoped `scopeActors` fixture when the goal needs a genuinely empty workspace or separate identities; do not truncate existing state. |
| **File uploads are limited to a synthetic CSV fixture.** `lib/upload.ts` drives the real file input with `catalog-regions.csv`. | Additional JSON/media or prompt bulk-upload shapes need separately planned fixtures; do not seed equivalent rows with SQL. |
| **OTLP seeding is a two-span JSON/HTTP tree.** `sendTrace` supports stable IDs/timestamps, recursive typed root/child/resource attributes and repeated calls for grouping. | Events, deeper trees and gRPC/protobuf still need a planned extension. See `harness/otlp-shapes.spec.ts` for exercised types, replay and grouping; this does not qualify voice transport or complete session/user UI journeys. |
| **The mock LLM is not programmable.** Only `echo: <last user message>`, fixed usage, OpenAI format.                                                                            | Shape the prompt so the echoed text parses (see `harness-cheatsheet.md`). Tool calls, JSON mode, per-request responses, 429/500 injection, latency injection and non-OpenAI formats need a new mock capability.                                                                                                                                                                                                                                            |
| **No email sink.** No mailhog or mailpit.                                                                                                                                      | Activation, invite, password-reset and magic-link flows cannot be asserted through mail. OSS signup yields an already-usable user, so those paths have no hook at all.                                                                                                                                                                                                                                                                                     |
| **No WebSocket or SSE assertions** in the probe.                                                                                                                               | Backend push and streaming surfaces are unobservable.                                                                                                                                                                                                                                                                                                                                                                                                      |
| **No Temporal probe.** No way to look up a workflow or schedule by id, or force a tick.                                                                                        | API polling with `POLL.EVAL_RESULT` / `POLL.ASYNC_JOB` is the only wait available.                                                                                                                                                                                                                                                                                                                                                                         |
| **No Redis, RabbitMQ or MinIO probes.**                                                                                                                                        | "The artifact landed in the bucket" and "the cache key was invalidated" cannot be asserted.                                                                                                                                                                                                                                                                                                                                                                |
| **Services the profile does not start:** `serving`, `code-executor`, the simulation runner, sized workers.                                                                     | Prompt-playground executions, code-eval templates and anything routed through `serving` are untestable here. Raise it in the interview — this is the "not reachable on this stack profile" ask-condition.                                                                                                                                                                                                                                                  |
| **Native CDC depends on the active mirror schema.** Score and simulation-definition create/edit/soft-delete are exercised by `harness/native-cdc.spec.ts`; nullable timestamp representation differs between PG and CH. Unfiltered eval graphs retain a separate dropped-table warning. | Run the native CDC harness before dependent flows. Table existence alone is insufficient; fresh-bootstrap and unfiltered-graph coverage remain separate gates. Do not patch source data or bypass CDC to make a test pass. |
| **No page objects or navigation helpers.** No "open project", "open the trace drawer", "open the Evals tab", "open the filter panel".                                          | Re-derive locators and URLs from the pinned facts in `harness-cheatsheet.md`. The three `data-filter-*` hooks listed there are the ones the shipped observe flow pins, not the only ones in product code — grep the whole tree (`grep -rn 'data-[a-z-]*=' frontend/src/sections frontend/src/components`; section directories are named after frontend features, not e2e areas) and use what is already there before concluding a new attribute is needed. |
| **No clock control, no feature-flag toggling.**                                                                                                                                | Time-dependent behaviour has to be planted on the wire (create the row already aged) rather than waited out. Note in the plan that this is what you are doing.                                                                                                                                                                                                                                                                                             |
| **No seeding helpers** for datasets, prompts, experiments, simulations or eval templates beyond raw API calls.                                                                 | Pin every wire body from a captured request or the serializer.                                                                                                                                                                                                                                                                                                                                                                                             |
| **Attach mode cannot override the in-container gateway address or key**, and the collector's host ports bind to `127.0.0.1` only.                                              | Eval flows are not attachable to a remote stack. Iterate them against the managed stack.                                                                                                                                                                                                                                                                                                                                                                   |
| **Chromium only**, desktop viewport, video off.                                                                                                                                | No mobile, WebKit or Firefox coverage; no visual-regression and no accessibility checks.                                                                                                                                                                                                                                                                                                                                                                   |
| **No cleanup or teardown utilities**, by design.                                                                                                                               | A long-lived local stack accumulates orgs and projects. The only reset is `bin/e2e down -v && bin/e2e up`.                                                                                                                                                                                                                                                                                                                                                 |
| **No local build target for `agentcc-gateway`.** `bin/e2e build` handles backend, frontend and collector only.                                                                 | Gateway changes are exercised as built code in CI. Locally, set `AGENTCC_GATEWAY_VERSION` yourself.                                                                                                                                                                                                                                                                                                                                                        |
| **No `@live-llm` example flow** and no documented pattern for a real-provider secret in CI.                                                                                    | The tag exists only as a grep-invert. A flow needing a real provider needs that pattern designed first.                                                                                                                                                                                                                                                                                                                                                    |

## Adjacent, not gaps

These look like gaps and are not — they are the harness working as intended:

- **No retries.** Deliberate. A flow that passes on the second attempt is reporting a real product
  behaviour; quarantine it with owner, ticket and expiry instead.
- **No global cleanup.** Isolation comes from a fresh per-worker org plus minted names.
- **`harness/**` runs alongside flows.\*\* Run it first after a boot to tell "the stack is wrong" from
  "my flow is wrong".
