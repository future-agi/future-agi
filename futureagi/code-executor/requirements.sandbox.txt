# Python libraries of the nsjail code-executor (futureagi/code-executor-base):
# what sandboxed user code can import, plus the executor's HTTP server.
#
# Every version below comes from futureagi/uv.lock, the resolution the backend
# image ships. Standalone runs code evals in the platform image, on the
# backend's site-packages, so pinning to the same versions makes a code eval
# return the same result there and in this nsjail executor (Standalone's
# `sandbox` profile, Distributed and Helm). (The old
# Dockerfile.base installed these unpinned: the last published base had
# pandas 3, numpy 2.4 and scikit-learn 1.9, while the backend had pandas 2.3,
# numpy 2.3 and scikit-learn 1.8.) jinja2 is on the backend sandbox's
# SAFE_MODULES list (agentic_eval/core_evals/fi_utils/sandbox.py), so it is
# importable here too. falcon and gunicorn run the executor's HTTP server
# (server.py) and are not in uv.lock; they stay at the versions the last
# published futureagi/code-executor image shipped (falcon 4.3.1's wheel is
# 0.9 MB, 4.0.2's Cython build 11.7 MB).
#
# Regenerate after a backend re-lock, from futureagi/ (so uv.toml applies):
#   uv export --frozen --no-hashes --all-extras --no-emit-project -o /tmp/lock.txt
#   uv pip compile /tmp/sandbox.in -c /tmp/lock.txt --python-version 3.11 \
#     --python-platform x86_64-manylinux_2_28 --no-header --annotation-style line
# where /tmp/sandbox.in lists: numpy pandas pillow scipy scikit-learn requests
# httpx nltk rouge-score levenshtein jinja2 falcon==4.3.1 gunicorn==26.0.0.
