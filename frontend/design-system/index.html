Future AGI Design System

One set of tokens, components and rules for the whole Future AGI product, in light and dark. Every screen draws each thing one way, from one shared component, and the rules are checked in code so the product stays consistent as it grows.

Data over decoration

Facts, numbers and status do the work: no tinted cards, emoji or ornament.

Calm by default

Neutral greys and flat surfaces; colour only when it means something.

Dense, but easy to scan

More on screen; hierarchy comes from weight and grey, not size.

Say less, plainly

Short text in the user's words; anything longer is a docs link.

Nothing left undesigned

Every state, in both themes.

Getting started

Tokens live in one file and are generated into CSS variables, a docs bundle and an MUI theme. Change tokens/tokens.json, run the build, and every output updates.

One name, two themes. Components use semantic tokens only (fg.secondary, border.default). No hex values and no isDark checks in components.

Foundations

Tokens and rules every component is built from.

Colour

Two tiers. Primitives are raw ramps and are never used in components. Semantic tokens name a job (“secondary text”, “panel background”) and point at a primitive per theme. The neutral ramp is zinc: the same family in both themes.

Greys do the structure. Purple marks the one main action, focus and AI. Green, amber, red and blue only ever mean a status.

Primitives

Semantic tokens

TokenLightDarkUse
Do
  • Pick the token by its job, not because its colour looks right.
  • Use bg.hover / bg.selected (alpha) so states work on any surface.
  • Use fg.tertiary for meta text; it passes AA on every surface.
Don't
  • Write hex values or primitives in components.
  • Use purple for avatars, tags, chips or secondary buttons.
  • Use fg.disabled for anything a person needs to read.

Status and data colours

Six status roles, each with a tint, a border, readable text, a solid fill and a label colour for that fill. Chart and category colours are a separate set of eight, so a chart series never reads as “failed”. dataMono is a quieter set of eight purple shades for charts that read better in one colour family, such as cost by group.

Contrast

Checked by the build in both themes. Text needs 4.5:1; icons and focus rings need 3:1. Alpha fills are measured over the panel background.

PairTokensLightDarkMinimum

Typography

Inter, three weights (400, 500, 600), tabular figures for numbers. Line heights sit on a 4px grid. body-sm (12px) is the UI default; body-md (12/18) is for long reading text. 12px is the largest body size; nothing uses 13px. Legacy variants map onto the scale: s1 12, s3 11, m3 12, m1/m2 15.

Do
  • Make a name stand out with label-md (500) and fg.default.
  • Put descriptions under names in caption and fg.tertiary.
  • Use overline only for short section labels.
Don't
  • Use 700 or bold anywhere; 600 is the heaviest weight.
  • Use sizes outside the scale (10, 10.5, 11.5, 12.5, 14px).
  • Set text below 11px.
  • Set code identifiers in bold; monospace names in rows are 12/400.

Writing

Words are part of the interface. Say what it does and what to do next, in the user's words.

Helper text is one line, two at most

Descriptions, subtitles, helper text, notices, dialog bodies and hover hints: one line where possible, never more than two (about 140 characters). Say what it does and what to do next; cut the why, the edge cases and the history. Anything longer is a docs link, never another paragraph.

The user's words

Name things by what people recognise: "Run simulation", not "Execute job". No internal words (project phases, document names); something not built yet is "Coming soon".

Sentence case, verb first

Sentence case everywhere, including buttons, titles, tabs and menus; uppercase only through the overline. Buttons start with the verb that says what happens ("Build environment"); a confirm button repeats the dialog title's verb.

Errors say what failed and what to do

No apology, no exclamation marks: "Couldn't reach the agent. The endpoint returned 502. Check it's running, then retry."

Real numbers and units

Digits and real units ("4m 31s", "96 of 113", "1.8s"). A dash — means "no value yet"; never "N/A" or "null". No emoji.

Spacing

A 4px grid with a 2px half step. The MUI theme keeps its 8px unit (theme.spacing(1) = 8px), so write these values in px. Common gaps: 4 inside controls, 8 between controls, 12 inside panels, 24 between panels, 32 between page sections.

Radius and borders

Six radii, each with a job. Every border is 1px; 2px is only for the selected tab indicator and focus.

Do
  • Controls 6, panels and menus 8, dialogs 12.
  • Use border.default around things and between table rows; border.subtle only for dividers inside a panel.
Don't
  • Put a coloured stripe on one edge of a rounded card. Use a header label or a tint instead.
  • Use dashed borders except for drop zones.

Elevation

Four levels. Everything in the page is flat with a 1px border, never a shadow. Floating layers get a 1px ring plus a soft shadow; in dark mode they also sit on a lighter surface, because shadows barely show on dark backgrounds.

Focus

Shown on keyboard focus only (:focus-visible). Buttons, links and checkboxes get a 2px border.focus outline outside the control; tabs, menu items, nav items and table rows draw it inside; inputs switch to the focus border with a soft 3px ring.

Sizing and density

Controls share heights so toolbars line up: a 32px button sits next to a 32px input. Tables default to 36px rows, 48px for two-line rows (name plus description); headers, inputs and tabs are 32.

TokenValuesUse

Motion

Productive and quick: things appear with ease-out, leave with ease-in, and move with ease-in-out. Nothing animates for decoration. Motion turns off under prefers-reduced-motion. Hover a tile to compare.

Icons

One set: Solar, linear style, through Iconify. Brand marks come from logos or simple-icons. Sizes 12, 14, 16 (default), 20. Icons take icon.default next to text and icon.strong on icon-only buttons.

solar:record-circle-linear is never used. Dataset table column-type icons keep their original set (agreed exception).

One exception, where Solar has no glyph: Fix uses ph:screwdriver (Phosphor regular, the closest stroke to Solar linear). Add an exception here before using another set.

Money and cost

How credits, estimates and costs are shown.

Credits and money states

Amounts are in credits with digits and the unit ("1,971 credits"); money paid outside the platform is shown apart, in its own currency. An estimate reads "≈ 90 credits" or "Up to 4,300 credits". Estimated, held, used and pending are different words, never interchangeable. An unknown amount reads "unknown", never 0 or "free".

Colour for money

Money is neutral text. A limit reached is amber (warning), not red; red is only for a failure. Held or released amounts are quiet (fg.tertiary).

Cost tables

Costs use the system table, full width like any results tab: one row per item with quantity × rate and credits right-aligned in tabular numbers, a bold total row with a plain label ("Charged", "Up to", "Spent"), and one note line under the table for rates and limits. A part breakdown is Part · Conversations · Credits.

A price on a paid action

A button that costs something shows its price after the label until it's charged ("Debug failures · ≈ 5 credits"). Why something stopped is said in words ("Limit reached", "Stopped early"), never a code.

Scores and deltas

A score is a number in fg.default, not a coloured pill. Colour goes on the change: green when it improved, red when it got worse, grey when flat. If a lower number is better (latency, cost), the colour follows better or worse, not the arrow.
